# Plan

## Purpose and boundaries

- Use only synthetic data generated by our own script.
- Never contact owners or any other person.
- Never close campaigns or change repair records.
- Repair notes are displayed as text only. They are never treated as instructions and never change the tool's behavior.
- The tool only flags and reports. It never contacts owners or changes source records.

## Current alignment and assumptions

- **Seller / dealer:** Treat the seller as the dealer. Assume the seller performs the repairs and maintains sales and repair records.
- **Manufacturer:** Maintains models, built vehicles, and campaigns. The working assumption is that the manufacturer mails recall letters; the client still needs to confirm this responsibility.
- **Central body:** Supplies current-owner and vehicle-status information. For this synthetic project, treat this source as the source of truth for both.
- **Tool:** Checks the supplied records, flags cases for human review, produces reports, and keeps the check history. It never performs owner outreach, closes campaigns, or changes source records, including repair records.
- **Relative data quality:** Assume manufacturer and seller data is relatively better maintained than central-body data. This is a project assumption. The synthetic inputs still include deliberate missing or conflicting records.
- **Input format:** All source data will be supplied as CSV files. Spreadsheets can be exported to CSV before import.

## Data sources

There are three sources, joined by **VIN**:

1. **Manufacturer:** Models, every VIN built, vehicle build dates, and recall campaigns with their model and build-date ranges.
2. **Seller / dealer:** Individual vehicle sales records, including buyer, seller, and sale date, plus repair records.
3. **Central body:** Sales, resales, current ownership, and records of scrapped, stolen, and exported vehicles.

All data is synthetic, generated by our own script, and deliberately messy so the checks can find missing or conflicting records.

## Affected vehicles and the active list

- A vehicle is affected when its model matches the campaign and its build date falls within the campaign's build-date range.
- Use the central body's records to determine the current owner and vehicle status.
- Remove scrapped, stolen, and exported vehicles from the active list. Keep their records and history.

## Recall notices

- First-class mail is the only notice channel.
- A returned letter counts as **not notified**.
- Owners must be mailed within **60 days of the campaign report to NHTSA**, the U.S. recall regulator.
- Record the report date, mailing date, recipient, and whether the letter was returned so the checks can evaluate these rules.
- The working assumption is that a new owner should be notified when a vehicle is resold after its recall letter. The client still needs to confirm this rule.

## Checks and flags

1. **Rule 1 - Missing notice:** Flag an affected vehicle whose owner was never mailed once the 60-day notification deadline has passed.
2. **Rule 2 - Repair overdue:** Flag a vehicle that was mailed but is still unrepaired after **X days**. The client has not set X yet.
3. **Source disagreement:** Flag a vehicle as **needs a human look** when the seller's and central body's records disagree about it.

## Check history

- Save every check with its date, rule, and reason.
- Keep the history so the team can review what was checked, what was flagged, and why.

## Open questions

- Confirm that the manufacturer is responsible for mailing recall letters.
- **What is a long time?** Set **X**, the number of days before an unrepaired vehicle triggers Rule 2, and confirm which date starts that clock.
- **How do we say an owner was never notified?** Agree which records establish notification and how to handle a missing mailing record, a returned letter, and a change of owner.
- Confirm that a resale after a recall letter requires a notice to the new owner.
- Confirm whether Rule 1 also flags returned letters: these count as not notified, but the current Rule 1 wording specifically says the owner was never mailed.

These resources inform the project. The central-body feed in this plan is a synthetic project model.
